# Security implementation and release gates

Implemented: salted ASP.NET Core Identity PasswordHasher (PBKDF2, 210,000 iterations for registered accounts), 12-character minimum, five-attempt/15-minute lockout, security stamps, single-use hashed verification/reset tokens, short-lived signed JWTs, serializable refresh rotation, family revocation on replay, current-account checks on every API/cookie authentication, tenant service authorization, role restrictions, SQL parameterization, concurrency tokens, hashed invitation tokens and audit events. Cookie sessions are HttpOnly/SameSite=Lax and require TLS outside Development; MVC forms validate antiforgery tokens. Razor escapes stored content. CSP prohibits scripts, remote assets and framing. API CORS is disabled. Production hosts enforce HTTPS/HSTS. Auth endpoints are IP-rate-limited in API.

No provider credentials are stored in this phase. Production key custody, encrypted OAuth storage, per-tenant job limits, crawler SSRF protection and publish approval enforcement are required before those modules become available. Domain normalization is input validation only: it is not DNS/redirect SSRF protection and does not authorize crawling. Sites start unverified, and no crawl/publish API exists yet.

Release gates: configure trusted TLS, least-privilege SQL login, SMTP, persistent protected Data Protection keys, proxy/IP handling for trusted infrastructure, centralized structured-log retention, backup/restore drills, dependency scanning and penetration/load testing. API rate limits are process-local and need a shared gateway for multiple instances. Public self-registration currently creates organizations without plan quotas. Invitation tokens use manual secure distribution. Membership management has deactivation but no reactivation/role-edit workflow yet. Email delivery is synchronous; a durable outbox is a follow-up. Bootstrap is operator-only and grants no implicit access to other tenants.

Password/reset/verification raw tokens must never be logged or committed. Development outbox files contain temporary secrets and must stay outside static file roots. User-secrets is a developer convenience, not a production vault. Runtime SQL errors are sanitized for API clients. Production MVC errors use a generic page. Long-term retention, deletion/export policies and MFA remain future hardening work.
